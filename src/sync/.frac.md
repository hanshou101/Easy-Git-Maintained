## 1. 本目录是什么

Easy Git 的同步领域核心。这里完成本地/远端扫描、三方分类、冲突处理、Markdown 往返变换、备份、pull 落盘和远端原子提交；除 `engine.ts` 外，多数模块保持为可独立验证的纯逻辑。

## 2. 直属文件

- `engine.ts`：单个 mapping/目标的九步同步编排；固定远端快照、按 mapping 生成规范 push 字节并扫描、分类、三方合并、冲突 UI、备份、按 pull 策略落盘、GitHub 原子提交或 Forgejo contents API 写入，并对非快进最多退避重试三次。
- `classifier.ts`：按 `push | pull | both` 对 local/remote/last-known 三态分类，输出文件动作、冲突和单向同步提示；把用户冲突选择转换成可执行计划。
- `blob-sha.ts`：计算 Git blob SHA-1，处理 base64、UTF-8/BOM 与文本文件判断，确保本地文件身份与远端一致。
- `wikilink-rewrite.ts`：只在 Markdown prose 中把 Obsidian embed 改写为 GitHub 可渲染链接，并收集 mapping 外附件；代码块与不可安全转换的链接保持原样。
- `markdown-transforms.ts`：对 callout、高亮和 math phantom 做带标记的 push 改写及 pull 还原，目标是无损往返。
- `line-endings.ts`：实现 push `preserve|lf` 与 pull `preserve|crlf`；仅转换可能的文本文件、保留 UTF-8 BOM、二进制直通，并让三方合并选择与远端规范一致的换行符。
- `exclusion.ts`：实现 `*`、`**`、`?`、目录后缀和 basename 匹配的最小 glob 排除器。
- `hidden-paths.ts`：判断路径中是否存在 dotfile/dot-directory 段，供 adapter 补扫隐藏路径。
- `commit-message.ts`：用 mapping、vault、文件计数和时间等上下文替换提交消息模板 token。

## 4. 本层约束 / 约定 / 禁忌

- GitHub 推送必须是基于固定 head 的单父提交，ref 更新禁止 force；并发移动由完整重跑解决。
- `pull` 与 `push` 是各自来源为真的镜像语义；`both` 才使用 last-known 作为三方祖先，不能把三种方向混成同一分类分支。
- pull 覆盖/删除前必须备份用户文件；取消冲突对话框时不得产生本地或远端副作用。
- 扫描 SHA、冲突合并和上传必须使用同一份规范 push 字节；pull 的 CRLF 只是 vault 表示，不能反向污染远端 blob 或制造第二次同步 modified。
- 文本变换必须保护代码块与 BOM；Markdown push 变换需要有对应 pull 还原，换行策略只作用于可能的文本路径。
- `.easygitignore` 与全局排除规则叠加；隐藏文件补扫仍必须尊重安全排除路径。

## 5. 什么时候需要下钻

- 改完整同步顺序、备份或 provider 写策略时先读 `engine.ts`。
- 改冲突/单向语义时读 `classifier.ts`；改 Markdown 或工作区/仓库字节表示时同时读 `wikilink-rewrite.ts`、`markdown-transforms.ts`、`line-endings.ts`。
- 改文件身份、二进制处理或隐藏路径时读 `blob-sha.ts`、`hidden-paths.ts` 和 `exclusion.ts`。
