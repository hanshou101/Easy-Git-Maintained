## 1. 本目录是什么

远端 Git 服务适配层。它把认证、HTTP 传输和 Git 数据操作封装成供同步引擎使用的 API，并在 GitHub 与自托管 Forgejo/Gitea 差异处做局部适配。

## 2. 直属文件

- `auth.ts`：PAT 校验、GitHub Device Flow 的开始/轮询、认证状态与错误文案；自托管服务在 `/user` 无权限时用仓库级接口验证 token。
- `client.ts`：基于 Obsidian `requestUrl` 的带认证 HTTP 客户端；统一 JSON、分页、错误和 rate-limit 信息，并对 GET 禁用缓存以防读取旧 branch/tree。
- `git-data.ts`：列仓库/分支、固定 head、遍历 tree、读写 blob/tree/commit/ref；Forgejo/Gitea 的响应差异和 contents API 写入策略收敛在这里。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- token 只能进入目标 Git 服务的认证请求；GitHub Device Flow 端点不得被自托管 base URL 替换。
- GitHub 现有请求路径和 Git Data 原子提交语义应保持不变；provider 差异必须在明确分支中处理。
- 更新 ref 必须 `force: false`，把 422 作为非快进竞争交给引擎重试，而不是覆盖远端。
- 改 workflow 文件的 API 失败要保留清晰的 workflow 权限提示。

## 5. 什么时候需要下钻

- 改认证或 token 生命周期时读 `auth.ts` 与 `client.ts`。
- 增加 provider、调整 branch/tree/blob/commit 行为或并发保护时读 `git-data.ts`，并同时下钻 `../sync/.frac.md`。
