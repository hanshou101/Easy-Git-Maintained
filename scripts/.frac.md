## 1. 本目录是什么

不依赖 Obsidian 实例即可运行的回归验证脚本。它们用 Vite（SSR 模式、内存输出）打包目标 TypeScript 与必要 stub：测试源码是一个虚拟 `.ts` 入口，`./src/...` 相对仓库根解析；需要 `obsidian` 的脚本由 `resolveId`/`load` 插件把它换成桩模块；打出的 ESM 以 data URL 在 Node 中执行，检查最容易被平台和字节差异破坏的同步路径。

## 2. 直属文件

- `crlf-regression.mjs`：覆盖 push `preserve|lf`、pull `preserve|crlf`、第二次同步 noop、UTF-8 BOM、二进制绕过、三方合并及 wikilink/callout/高亮/math 往返，确保仓库与工作区表示不会反复翻转。
- `hidden-path-regression.mjs`：用内存 adapter 验证 dotfile/dot-directory 扫描、隐藏路径采用同一 push 规范 SHA、`.easygitignore`/安全排除、备份删除以及 workflow 权限错误提示。
- `submodule-regression.mjs`：用内存 adapter 验证本地扫描只排除 `.gitmodules` 声明的子仓目录及其孙仓、`.git` 内部文件；仓库自身文件、未声明的嵌套仓和直接被映射的子仓自己的文件照常同步（整库映射、仓库根映射、子仓根映射三种拓扑）。
- `upstream-plugin-regression.mjs`：打包真实的 `src/main.ts` 与 `src/upstream-plugin.ts`，`obsidian` 换成能构造插件的桩（Plugin 的 loadData/saveData/addCommand 记录、Notice 收集）；验证上游 `easy-git` 启用且已安装时 `onload()` 只弹不消失的通知、不注册命令、不写 data.json，残留的启用记录不算；首次启动接手上游 data.json（含手动安装在别名目录、mapping 同步状态、keychain 里的 token、旧版明文 token），之后只读自己的 data.json，自己的 data.json 读坏时不接手。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- 四个脚本分别由 `npm run test:crlf`、`npm run test:hidden`、`npm run test:submodule` 和 `npm run test:upstream` 调用，断言失败必须以非零状态退出。
- stub 只替代 Obsidian 运行环境，不应复制一份待测算法；待测实现仍从 `src/` 打包进入脚本。
- 模板字符串里的测试源码与 stub 就是断言本身，换打包方式时只改文件头和末尾的打包段；解析不到的导入（包括没有 stub 的 `obsidian`）必须让打包直接失败，不能被悄悄外置。
- 修改换行策略时必须同时证明“扫描 SHA = 实际上传字节”以及 pull 写盘格式；隐藏路径、Markdown 变换或 workflow 权限错误变化也应扩充对应脚本。

## 5. 什么时候需要下钻

- 排查平台换行/BOM 问题读 `crlf-regression.mjs`；排查隐藏文件或 adapter 行为读 `hidden-path-regression.mjs`；排查子仓/嵌套仓被误排除或漏排除读 `submodule-regression.mjs`；排查与上游插件并存、换装后设置没接上读 `upstream-plugin-regression.mjs`。
