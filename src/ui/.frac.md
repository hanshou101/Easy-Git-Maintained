## 1. 本目录是什么

Obsidian 原生组件构成的交互层。这里负责 mapping 编辑、远端选择、冲突决策、认证、诊断、同步日志与状态反馈，不承载同步分类算法。

## 2. 直属文件

- `mapping-modal.ts`：创建/编辑 folder mapping 及多个 destination，校验文件夹、仓库、分支、方向、push/pull 换行策略和自动同步模式。
- `pickers.ts`：vault 文件夹、仓库、分支、远端文件夹和 mapping 名称的异步/模糊选择器。
- `conflict-modal.ts`：逐文件选择保留本地、远端或双方，并只在选择对冲突类型有效时提交结果。
- `device-flow-modal.ts`：显示/复制 GitHub 设备码、打开验证页并按服务端节律轮询授权结果。
- `diagnose-modal.ts`：采集 mapping（含 push/pull 换行策略）、本地文件、远端树、排除规则、凭据和 API 状态，生成可复制的诊断报告。
- `sync-log-modal.ts`：过滤和展示最近同步流水、错误与文件清单。
- `status-bar.ts`：聚合全部 mapping 的同步中、失败、最近成功或待命状态，并维持相对时间刷新。
- `confirm-modal.ts`：通用 Obsidian 确认对话框，替代浏览器原生 `confirm`。
- `button-compat.ts`：集中处理破坏性按钮样式兼容，避免各 modal 重复实现。

## 3. 子目录导航

无直属子目录。

## 4. 本层约束 / 约定 / 禁忌

- 使用 Obsidian `Modal`、`Setting`、`FuzzySuggestModal` 和 DOM helper；禁止 `innerHTML` 及原生 `alert/prompt/confirm`。
- provider 特有认证字段只能出现在认证或选择流程，per-mapping 编辑面不能膨胀出 provider 专属配置。
- modal 关闭/取消必须明确回传取消状态并清理轮询、ticker 或临时 DOM，不能误触发同步副作用。
- UI 只收集与展示状态；分类、文件动作和网络写入仍由 `../sync/` 与 `../github/` 负责。

## 5. 什么时候需要下钻

- 改 mapping 数据录入或工作区/仓库换行选项时读 `mapping-modal.ts` 和 `pickers.ts`，并核对 `../sync/line-endings.ts`。
- 改冲突、安全确认或 OAuth 时读对应 modal；改排障能力时读 `diagnose-modal.ts` 与 `sync-log-modal.ts`。
